1. Sign-up to first agent

  1. Sign-up form asks for name, email, password, mobile and terms only. GET /api/v1/auth/signup/options tells the page whether verification is by email, SMS or unavailable. web/signup.html → POST /api/v1/auth/signup → agent/auth_manager.py (validates before creating; the workspace starts pending)
  2. Email code. A 6-digit code is mailed to the address (30-minute life). No mail transport configured means the step reports verification_unavailable instead of pretending; MAIL_DRY_RUN=1 shows the code on screen for local testing. agent/mailer.py · POST /api/v1/auth/otp/verify, /api/v1/auth/otp/resend · transport set on /email-settings (Super Admin)
  3. Onboarding gate. A new Product Admin is redirected to /onboarding until it is finished. scripts/serve.py page gate · web/onboarding.html
  4. Firm details are typed in or read from the firm's website (SSRF-safe reader, then Gemini or a headings fallback). POST /api/v1/onboarding/website-draft → agent/website_scraper.py, agent/website_details.py
  5. Finish. Names the workspace, saves the firm profile and seeds an agent that is not live. POST /api/v1/onboarding/complete → agent/onboarding.py, agent/firm_profile.py

Roles: one Super Admin for the platform and one Product Admin per organization, enforced in agent/auth_manager.py. Member Admins (law staff) see only the cases assigned to them.

2. Numbers and trunks

  1. Marketplace. Lists Telnyx or Twilio numbers, filtered by country and search. Live carrier inventory is used when keys are present, otherwise a built-in catalog. The carrier chips count what those filters match. GET /api/telephony/numbers/available → TelephonyManager.list_available_numbers / list_carriers (agent/telephony_manager.py)
  2. Inbound trunk. Needs a name and at least one full E.164 number. Every DID on it becomes an owned number assigned to the active agent. POST /api/telephony/trunks/inbound → validate_inbound_trunk_payload(require_numbers=True) → ensure_owned_number
  3. Outbound trunk. Needs a SIP host[:port] and at least one caller-ID number. POST /api/telephony/trunks/outbound
  4. Assign. Each owned number names the agent that answers it. Trunks are removed with the …/delete routes. POST /api/telephony/numbers/update · /api/telephony/trunks{,/inbound,/outbound}/delete
Buying a number and dialling out are simulated. The marketplace never places an order with a carrier.

3. A phone call (Twilio media stream)

The default path for real phone calls. No LiveKit or SIP is involved: Twilio streams 8 kHz μ-law audio straight to the dashboard server.

  1. Twilio calls the webhook for the dialled DID. The X-Twilio-Signature is checked; a bad one gets 403. POST /api/telephony/voice/inbound → _maybe_twiml_webhook (scripts/serve.py)
  2. TwiML answer is <Connect><Stream> to /api/telephony/media-stream, carrying the called and caller numbers and a shared token (checked on the stream's start event, because Twilio drops query strings). agent/twilio_stream.py media_stream_token
  3. Agent chosen by the owned number's assigned agent, falling back to the active agent. A call_started webhook goes out. TwilioMediaStreamSession.on_start / _resolve_agent
  4. Listen. Caller audio goes to Deepgram streaming STT. When the caller speaks over the agent, its audio stops and the unheard part of the reply is dropped from history. _start_deepgram_stt · interrupt_agent · _truncate_unheard_reply
  5. Reply. The agent's reply uses global instructions first (no legal advice, how to end a call, answer firm questions only from the firm's details and files), then the agent's prompt, then the firm details read from the database at call time (30 s cache), then FIRM KNOWLEDGE: the passages from the firm's knowledge base that match the caller's last two turns. It is spoken in the agent's voice, converted to μ-law. agent_builder._preview_reply · knowledge_query · agent/firm_context.py call_instructions, knowledge_context · _speak_agent_text
  6. Goodbye. When a full reply reads as a sign-off, the stream is closed and Twilio hangs up. agent_builder.looks_like_closing → _hang_up_after_goodbye
  7. Stop. The transcript is handed to the post-call pipeline (section 5). With no caller turns, only a call_ended webhook goes out. TwilioMediaStreamSession.on_stop → pipeline_worker.enqueue_call / execute_job

4. A browser or SIP call (LiveKit)

  1. Room. The Agent Builder test call, the softphone or the browser SDK gets a token and joins a LiveKit room. In SIP mode a carrier INVITE reaches the project's SIP URI and a dispatch rule places it in a room. web/voice-client.js · web/softphone.html · agent/token.py · agent/telephony_manager.py dispatch rules
  2. Worker joins and loads the active agent: voice applied, prompt built by the same call_instructions as phone calls. agent/worker.py entrypoint · tts_manager.apply_voice
  3. Each caller turn rebuilds the instructions with that turn's FIRM KNOWLEDGE passages (in a thread, off the audio loop); the query_knowledge_base tool searches the same firm. agent/worker.py execute_llm_turn · call_agent · agent/tool_manager.py query_knowledge_base
  4. Conversation. Silero VAD for turns and barge-in, streaming LLM, streaming TTS, mid-call tools, transfer, DTMF/IVR, AMD, recording, all over the room's data channel. agent/llm_manager.py · tts_manager.py · tool_manager.py · transfer_manager.py · dtmf_manager.py · amd_manager.py · recording_manager.py
  5. End. Same sign-off detection, then the worker's own post-call pipeline. agent/worker.py → pipeline_worker.enqueue_call
The worker only sees code and .env changes after docker restart voice-agent-worker. A test that passes against the dashboard server can still fail through LiveKit until then.

5. After the call

Both processes run the same six-stage pipeline (agent/pipeline_worker.py). A failed stage is retried. Clio and case registration never block the job.

#StageResult
1audio_mixdownStereo WAV (left caller, right agent), energy metrics
2transcript_normalizationClean, time-aligned turns
3metrics_calculationTalk-time ratio, words per minute
4sentiment_analysisScore, trend, frustration, summary and action items (agent/sentiment_analyzer.py)
5schema_extractionTyped fields (e.g. legal_intake), then Clio Grow lead and/or Clio Manage contact and matter, then a case on the Cases page (agent/schema_extractor.py, agent/clio_connector.py, agent/case_manager.py)
6storage_archiveRecording and manifest archived; the call appears in Call History

Listening on the pipeline's events: signed HMAC-SHA256 webhooks to each subscribed endpoint (agent/webhook_dispatcher.py), and a short summary email to the agent's lead_emails when mail is set up (agent/onboarding.py notify_leads). Assigning a case to staff with a Clio user id sets the matter's Responsible Attorney.

6. Knowledge base

One library of files per firm, read once on upload and searched on every caller turn. Admins manage it on /knowledge.

  1. Upload. The file's bytes are the request body. Type is decided from the bytes (PDF, Word, Excel, CSV, text, Markdown, PNG/JPEG/WebP); limits are 20 MB a file and 200 MB / 300 files a firm; duplicates are refused. POST /api/v1/knowledge/upload → KnowledgeManager.upload, sniff (agent/knowledge_manager.py)
  2. Store. The record goes to app_documents (knowledge_files) and the original bytes to knowledge_blobs; JSON and files under config/knowledge/ without a database. agent/storage.py save_document, save_blob
  3. Read in the background. PDF text pages, Word paragraphs and tables, Excel rows and plain text are read on the dashboard server. Images and scanned PDF pages go to Gemini (one retry). The result is Ready or Failed with a reason. KnowledgeManager.process · extract · _gemini_read_image
  4. Split. Short overlapping passages (about 900 characters), never across PDF pages, saved to knowledge_chunks. split_passages
  5. Search. BM25 over the firm's ready passages, with stemming and a small set of receptionist synonyms. Other processes (the worker) reload when the collection stamps change. KnowledgeManager.search · _Index · storage.collection_stamps
  6. Use on calls. Each caller turn adds the best passages to the agent's instructions (sections 3 and 4). Nothing matching means the agent offers a call back. agent/firm_context.py knowledge_context

7. Case documents

Files on cases from staff, and from callers through a private link offered at the end of the call.

  1. Ask. The global rules have the agent ask about documents before its closing line, spell the email back and ask "Is that right?" on its own turn (a goodbye hangs up). agent/firm_context.py GLOBAL_INSTRUCTIONS
  2. Read the answer. After the call the transcript is read (Gemini, or rules on failure): asked, wanted, the confirmed email or phone. The case is registered with documents_request.status = requested. agent/documents_request.py detect → pipeline_worker → case_manager.register_from_call
  3. Send the link. A 43-character token (stored only as its SHA-256), one case, 7 days, 20 files; email when there's an address and mail is set up, else SMS. No public address means not sent, with the reason on the case. agent/upload_links.py send_link · POST /api/v1/case-documents/link (staff resend / copy)
  4. Caller uploads on /upload/<token> without signing in; per-IP limits stop guessing. Files are checked by their bytes and saved to the case as the caller's. web/upload.html · GET /api/v1/upload-link/info · POST /api/v1/upload-link/upload → agent/case_documents.py
  5. Tell the firm. The case counts new files (badge on Cases) until opened; one email per case per 10 minutes goes to the assigned staff and the firm's lead emails. notify_new_documents · POST /api/v1/case-documents/seen

Testing: what is safe to run

These touch real systems. Run them only when that is the point.
  • scripts/verify_super_admin.py: drives the live server on 8091 and the real database; it creates accounts that stay behind.
  • scripts/test_clio_integration.py --live and scripts/simulate_call_to_clio.py: send leads to the real Clio account. The default --mock mode is safe.
  • scripts/sip_probe.py: sends a real SIP INVITE to the LiveKit SIP URI.
  • scripts/test_playwright_voices.py and Agent Builder's Test Call: live calls through the Docker worker, saved to the real Call History, even when the dashboard server is an isolated copy.
  • Any script run from the repo folder that imports agent/ reads .env, including DATABASE_URL. Prefix it with DATABASE_URL= unless the database is the point.
  • scripts/backfill_cases.py --apply, scripts/enforce_admin_slots.py --apply: write to the shared database (stop the server first for the second).

The newer suites never touch the real checkout. They copy agent/, scripts/, web/ and config/agents.json to a temp folder and start their own server on a spare port with DATABASE_URL empty, no .env, carrier and mail keys stripped, loopback trust off and dummy LiveKit credentials. New tests should do the same; scripts/verify_trunk_validation.py is a short example.

Running them

# one isolated suite (safe at any time)
python3 scripts/verify_trunk_validation.py

# the phase 1–5 regression set (needs the dashboard on 8091 and the worker)
python3 scripts/run_all_tests.py 8091

# every page as every role
python3 scripts/audit_all_pages.py

Each script prints [PASS]/[FAIL] lines and exits non-zero on any failure. Isolated suites keep their temp folder and print the server log path when something fails.

Testing: by hand

A real phone call

  1. On Phone Numbers, check the DID is active and assigned to the agent you mean to test.
  2. Call it. The greeting should match the agent's First Message, in its voice.
  3. Ask something about the firm: the answer should come from the saved firm details. Ask for legal advice: the agent should decline.
  4. Say goodbye and let the agent finish: the line should drop by itself.
  5. Within a minute the call should appear in Call History with a transcript and summary, a case on Cases, and the webhook deliveries on Webhooks.

A browser call

Agent Builder → Test Call exercises the LiveKit worker. If its behaviour lags a change you just made, the worker has not been restarted.

Sign-up locally without real email

Run an isolated copy (see above) with SIGNUP_ENABLED=1 MAIL_DRY_RUN=1 on a spare port; the code is shown on screen.

Known gaps

AreaState
LiveKit hang-upopen The worker skips the hang-up when the caller talks over the goodbye.
verify_sip.pyopen 3 of 5 checks fail against the current config/sip_trunks.json, which no longer has trunk-primary or an outbound trunk. The suite expects the demo trunks.
Firm scopingopen Agents, the live agent, webhooks, the Clio token and branding are server-wide, not per firm.
Intake namesopen The regex extractor can take the agent's greeting as the client name; Cases filters it, but Clio can still receive it.
Carriersby design Number purchase and outbound dialling are simulated.
Booking toolsopen check_availability, book_appointment and lookup_order are simulated; saved copies in config/custom_tools.json make them echo instead. Turn them off for agents until a real calendar is connected.
Caller upload linkssetup Sent only with PUBLIC_BASE_URL set; email needs Email delivery; SMS on a Twilio trial reaches verified numbers only.
Knowledge searchby design Word matching, not meaning: a question sharing no words (or synonyms) with a file won't find it.
