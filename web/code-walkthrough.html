2. The End-to-End Real-Time Media Pipeline

  1. Audio Input: Caller speaks into the browser microphone. Audio is encoded into Opus and transmitted over WebRTC RTP packets to the LiveKit server.
  2. Voice Activity Detection (VAD): The agent worker feeds incoming 16kHz audio slices to Silero VAD. If the AI is currently talking, VAD immediately triggers Barge-In, aborting speech playback in under 50ms.
  3. Speech-to-Text (STT): Deepgram Nova-2 processes the audio stream via WebSockets, emitting interim hypotheses and finalized sentences.
  4. Dialogue Manager: When the user stops speaking, the utterance is sent to the LLM. If the user asks for a database lookup (e.g. checking appointment availability or order status), the Filler Speech Engine immediately speaks a natural filler phrase (e.g. "Checking available times for you right now...") in under 10 microseconds while the tool executes asynchronously.
  5. Clause Boundary Splitting: The LLM streams tokens into a clause splitter that breaks sentences at commas and periods.
  6. Speech Synthesis (TTS): The first clause is sent immediately to the TTS engine (Deepgram Aura 2 or Cartesia Sonic), producing 24kHz audio frames sent back over WebRTC so the user hears speech in sub-second latency.

Lines 314–330: Web Audio API Volume Meter & FFT Analyser

function startMeter(track) {
  audioCtx = new (window.AudioContext || window.webkitAudioContext)();
  var src = audioCtx.createMediaStreamSource(new MediaStream([track.mediaStreamTrack]));
  var analyser = audioCtx.createAnalyser();
  analyser.fftSize = 512;
  src.connect(analyser);
  var buf = new Uint8Array(analyser.frequencyBinCount);
  (function tick() {
    analyser.getByteTimeDomainData(buf);
    var peak = 0;
    for (var i = 0; i < buf.length; i++) peak = Math.max(peak, Math.abs(buf[i] - 128));
    var pct = Math.min(100, Math.round((peak / 128) * 160));
    $("level").style.width = pct + "%";
    raf = requestAnimationFrame(tick);
  })();
}

Captures the local microphone audio track using the browser's AudioContext. An AnalyserNode computes the peak displacement from the neutral byte value (128) and animates the width of #level 60 times per second via requestAnimationFrame.

Lines 400–521: LiveKit Data Channel Multiplexer (DataReceived)

This is the primary messaging gateway. The Python agent worker broadcasts events as JSON packets over WebRTC data channels. The listener decodes each payload and branches by topic:

  • topic === "transcript" (Lines 400–412): Renders interim speech or finalized sentences into #tx.
  • topic === "vad" (Lines 413–425): Toggles the VAD badge between Speaking and Silent.
  • topic === "agent_state" (Lines 426–453): Changes agent badges when the AI transitions between THINKING, SPEAKING, and LISTENING.
  • topic === "llm_stream" (Lines 454–457): Appends incoming tokens to the live dialogue box.
  • topic === "llm_clause" (Lines 458–467): Appends complete clauses into #clause-box.
  • topic === "agent_reply" (Lines 468–473): Updates the final performance metrics (TTFT, token count, clause count).
  • topic === "tts_metrics" (Lines 474–489): Displays Time-To-First-Audio (TTFA) and playback duration.
  • topic === "interruption" (Lines 492–501): Displays the barge-in cut-off banner and updates TTS status to Audio Cut-off.
  • topic === "tool_call" (Lines 502–506): Updates tool name and sets status to Executing....
  • topic === "filler_speech" (Lines 507–510): Displays the filler speech phrase emitted to prevent dead air.
  • topic === "tool_result" (Lines 511–520): Updates tool execution latency (ms) and success/fallback status.
