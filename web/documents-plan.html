Case Documents Plan

Cases get documents. Staff can attach files to a case, and at the end of every intake call the agent asks whether the caller has documents about their case. If they do, the caller gets a private upload link by email (or by text message when there's no usable email) and the files land on their case. All four phases are built and tested.

How it works for a caller

StepWhat happens
1. End of the callBefore saying goodbye the agent asks: "Do you have any documents about your case, like photos, a police report or medical bills?"
2. Caller says yesThe agent confirms where to send the link: their email, spelled back to them, or their mobile number.
3. After the callThe case is created and marked Documents requested. The caller gets a private link by email; by text message when no usable email was given.
4. Caller uploadsThe link opens a simple page (no account, phone-friendly) for that one case. PDF, Word, photos; valid 7 days.
5. Staff see themFiles appear on the case with who sent them and when; the case shows New documents until someone opens them.

Decided

  • Link by email, text message as backup when the caller gave no usable email. Staff can resend either from the case.
  • Links last 7 days and only ever add files to one case. They can't list, open or delete anything already there.
  • Accepted files: PDF, Word (.docx), images (PNG, JPG, WebP, HEIC from iPhones), text. Up to 20 MB a file and 20 files a link. Type checked from the file's contents.
  • Storage in PostgreSQL next to the case, scoped to the firm, the same way as the knowledge base.
  • Who sees documents: the firm's Product Admins, Super Admins, and the staff assigned to the case.

Before it can go live

  • Email isn't set up on this server. Fill in Email delivery (SMTP or Resend) so links can be sent. Until then the build is tested against a local test mail server.
  • Twilio is a trial account: text messages only reach verified numbers until it's upgraded.
